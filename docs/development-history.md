# 开发历程与证据索引

本页依据本地既有开发历程、阶段验收报告及当前源码整理。只摘取公开所需的技术范围、结果与失败原因，不复制原始审批、日志、个人信息或运行标识。Stage编号是阅读分类，实际先后关系以本页M/R/G里程碑为准。

## 如何理解证据

- **H证据**：本次实际阅读的历史阶段报告所记结论；原始材料仅本地保留。本页给出脱敏摘要，不伪装成可下载日志。
- **源码/测试链接**：可核对当前实现及覆盖意图；测试定义不是执行结果，当前文件也不能替代早期版本的完整源码。
- **PASS**必须带范围：离线/Mock、真实设施、真实模型或部署。FAIL/BLOCKED的历史记录保留；NOT_VERIFIED表示证据不足。
- 本次运行RAG、模型、数据库、构建和浏览器测试均为0。没有新Git提交，也没有创建Stage同名标签。

## 关键阻断及处理

| 问题 | 真实处理 | 不能扩大解释的范围 |
|---|---|---|
| Playwright Worker重载误报输出占用 | 检查移到单次入口，原子创建运行目录 | 不删除旧证据、不关闭冲突门禁 |
| Milvus路径被误当文件 | 按实际目录存储检查初始化状态和资源归属 | 不把所有文件检查替换为目录检查 |
| AI导航徽标影响文本定位 | 验收脚本改用稳定路由/语义定位，离线回归 | 不因此重写业务UI或重新上传已索引PDF |
| 无密钥基础设施入口缺失 | 明确infrastructure/real模式，统一执行边界阻止真实调用 | 设施PASS不等于Qwen问答PASS |
| 日常配置与实际限频不一致 | 单独批准后让5次/分钟生效，再核验持久账本 | 不因换容器或审批重置历史 |
| 墙钟与单调时钟采样错位 | 使用明确的采样区间和浮点精度边界 | 保留真实回拨、漂移及严格重启保护 |
| 新Epoch首次采样与自身比较 | 首次合法接管只建锚，后续再做连续性比较 | 不自动解除已有暂停 |
| 短期预检证据缺失/精度问题 | 整数纳秒判断，失败前持久化并回读原样本 | 原失败的现场原因仍不能反向补证 |
| 人工时间恢复 | 核对当前可信UTC、下界、无UNKNOWN/在途，再独立确认 | 历史完整单调连续性及Windows实时同步仍保留NOT_VERIFIED |

## 历史源码与版本边界

早期完整工程快照不足，不能把当前源码删减后伪装成M1～M5或某个v0.x版本。三份旧后端归档只能恢复对应后端组件，缺少完整前端和测试；它们留在原本地归档中，不进入发布源码。

当前发布仓库采用独立根提交，V1.0是源码能力描述。本页不虚构阶段提交、提交时间或同名版本标签。文档导航见[开发计划](development-plan.md)，八个专题从[Stage 1](stage1.md)开始。
