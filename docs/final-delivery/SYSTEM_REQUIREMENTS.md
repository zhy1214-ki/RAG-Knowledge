# 系统需求分析

> GitHub副本说明：标为“本地专用”的原始证据未纳入Git，不是可下载附件。分类及存在性见[本地材料索引](../LOCAL_EVIDENCE_INDEX.md)；不复制原始审计或用户数据来补齐链接。

版本：V1.0；资料截止：2026-11-18；M7只整理文档，不重新运行服务或测试。
依据：[实际路由](../../backend/app/api/base.py)、[ORM](../../backend/app/models/__init__.py)、[业务服务](../../backend/app/services/)、历史验收（本地专用材料，不随发布源码分发）。

## 1. 问题与目标

项目“知序”面向个人或团队资料的组织与查询：上传文档后提取文本、建立向量索引，
用户在自己拥有的知识库内提问，并查看与答案关联的文档片段。
系统希望提供可运行、可演示、可追溯的RAG流程，不声称消除模型幻觉或达到生产级可靠性。

V1.0采用已有预训练模型的推理接口，没有训练、微调或自行研发基础大模型。
当前8080为Mock演示；真实模型能力由两次受控历史验收支持，
新版UI本轮阶段的浏览器证据是合成API响应，不等于重新执行真实RAG。

## 2. 用户与场景

仅有普通注册用户，没有管理员/审核员等角色表或RBAC。
用户通过用户名、密码登录；只能访问自己拥有的知识库和会话。
跨用户访问已有资源按不存在处理，避免暴露归属信息。
没有团队共享、邀请成员、跨用户授权或组织级知识库。

典型流程：登录 → 创建知识库 → 上传文档 → 等待已索引 → 提问 → 查看回答及来源 → 恢复历史。
本轮只编写该流程的材料，不执行任何新增用户、上传、提问或删除操作。

## 3. 功能需求与已实现边界

| 编号 | 模块 | V1.0需求及实现 | 已有证据 |
|---|---|---|---|
| RF01 | 用户管理 | 注册、登录、查询当前用户；scrypt密码散列、HS256 JWT、退出清理浏览器会话存储 | M1/M4离线与隔离测试 |
| RF02 | 首页 | 当前用户知识库、文档、会话计数；快捷入口和最近记录；未知统计显示— | M6与M6.6 Mock UI |
| RF03 | 知识库 | 创建、列表、详情、编辑、删除；同用户名称唯一 | M1、PG及浏览器 |
| RF04 | 文档 | PDF/DOCX/TXT/Markdown上传、解析分块、进度/失败显示、状态查询、删除索引与文件 | M2/M4、真实PG/Milvus |
| RF05 | 智能问答 | 查询向量化、限定知识库检索、阈值过滤、Mock或Qwen回答、引用校验及显示 | M3及M5真实单样本 |
| RF06 | 会话历史 | 创建/列出/查看/删除会话、消息查询、继续问答；来源快照持久化 | M3、PG、M5及M6.6 |
| RF07 | 异常反馈 | 参数、格式、解析、数据库、向量、Embedding、模型、授权、内部错误分类脱敏 | M4安全测试及M6提示 |
| RF08 | 展示交互 | 浅色蓝色桌面UI、Markdown/代码、已有来源展开、上传及发送防重 | M6/M6.5/M6.6 |

RF02没有独立统计服务或专用统计表，而是前端聚合既有列表接口。
RF05为一次请求返回完整回答，不包含SSE流式输出、工具调用、Agent执行或联网搜索。
来源查看仅展开已返回文本，不是原文件在线预览/下载功能。

## 4. 输入与业务约束

| 对象 | 当前约束 |
|---|---|
| 用户名 | 3–64位ASCII字母、数字、下划线或短横线 |
| 密码 | 8–128字符；材料不提供任何真实或测试密码 |
| 知识库 | name必填1–120字符；description可选、至多4000字符 |
| 上传 | 每次一份；pdf/docx/txt/md；非空；默认20×1024×1024字节 |
| 解析 | 纯文本总长不超过2,000,000字符；DOCX解压声明总量不超过100MiB |
| 文本编码 | TXT/MD使用UTF-8-sig，允许BOM；不解析Markdown为网页 |
| 文本分块 | SentenceSplitter默认chunk_size=384、chunk_overlap=48；按其token计数规则，不是固定384字符 |
| 向量 | 固定1024维；真实Embedding每批最多10条；Mock与Qwen分集合 |
| 问题 | 1–4000字符；top_k默认5、范围1–10；默认min_score=0.2 |
| 模型上下文 | 最近10条历史；发给Qwen时每条截取4000字符 |
| PDF位置 | 实际提取页码，从1开始；DOCX等不推测页码 |
| 状态 | uploaded / processing / indexed / failed，删除中另有deleting |

前端对纯空白知识库名额外校验；后端KBInput的依据是长度限制，
数据库没有“禁止纯空白”的CHECK约束，不能将前端规则写成数据库保证。

## 5. 非功能需求

- 可维护：API、业务、模型适配、向量适配分层；通过环境变量配置。
- 数据隔离：所有权校验、Milvus知识库过滤、关系库再次核验indexed状态与归属。
- 一致性：索引失败补偿；删除先写deleting；成功回答后同次提交两条消息。
  这些是单实例补偿策略，没有跨PostgreSQL/Milvus/文件的分布式事务。
- 异常安全：不返回路径、密码散列、原始供应商异常或内部堆栈；日志为事件码与请求ID。
- 演示可用：保留Mock替身；Milvus Lite与进程锁要求单实例单worker。
- UI兼容：M6记录覆盖1024/1280/1440宽度；并非全浏览器/移动端兼容认证。
- 性能：未制定或验证并发吞吐、P95响应时延、检索准确率等量化SLA，标为NOT_VERIFIED。

## 6. 不在已实现范围的内容

OCR、SSO、角色权限、密码找回、令牌刷新/服务端注销、限流、配额后台、
持久化任务队列、混合检索、重排、文件预览、流式输出、高可用、多worker和远程正式部署均未实现。
真实验收脚本的请求计数与预算门禁属于受控验收设施，不是面向所有用户的全局计费产品功能。

## 7. 需求验收口径

离线/Mock、真实数据库及向量设施、真实后端模型、真实浏览器模型、8080新版UI分别记账。
不得用Mock PASS推导真实模型质量，也不能用一次TXT单问验收推导所有格式和问题均可靠。
需求到证据的对应关系详见 [测试报告](SYSTEM_TEST_REPORT.md)；
当前不足和材料清单见 [交付检查](DELIVERY_CHECKLIST.md)。
