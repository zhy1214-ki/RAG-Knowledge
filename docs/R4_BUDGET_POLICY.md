# R4 日/月预算及严格时钟政策

> GitHub副本说明：标为“本地专用”的原始证据未纳入Git，不是可下载附件。分类及存在性见[本地材料索引](LOCAL_EVIDENCE_INDEX.md)；不复制原始审计或用户数据来补齐链接。

本政策仅为待审批配置。用户已在本轮选择严格日期保护；实际运行环境尚未应用本改动。

## 1. 范围和持久计数

预算覆盖8081整个独立环境的所有用户、文档Embedding、查询Embedding和Qwen，使用同一PostgreSQL账本。
GuardState.historical_requests旧基线6保留；R3.3当前环境3条账本保留，已知累计9。
旧6次缺少此环境逐条计费记录，不伪造Token/费用补账，也不改基线为9后再加3。

发送前在事务中登记SENT_UNCERTAIN和保守费用，提交后才发送HTTP请求。
VERIFIED、UNKNOWN、SENT_UNCERTAIN等全部占请求数/预算；超时、失败、重启、换审批ID或日期都不删记录或返还预留。
成功按max(发送前估算, 实际usage估算)保留charge_cny，较低usage不退款。
这是保守预留，不是云账单金额；usage可分别从Token/脱敏MODEL_VERIFIED事件计算。

## 2. 多重门禁

必须同时满足：应用未暂停、无待确认已发请求、输入上限、全历史合计及类型上限、
每日次数、日预算、月预算、滚动60秒频率、单模型及单业务并发、防重复提交。

待审批：日¥0.10/月¥3，日60次、分钟60次、当前环境累计1000次、每类型1000次，
输入估算4096、输出256；单worker、单并发、自动模型重试0。
当前运行中的旧累计上限仍已耗尽，不因这份文档或示例文件获得新额度。

日/月费用和计数按ModelCall.created_at索引的UTC半开区间统计，不信任可改的day展示字段：
UTC日start, 次日start)，自然月[月首, 下月首)。
UTC日界线对应香港时间08:00；不是本地午夜，也不是滚动24小时/30天。
每日与每月均按charge_cny保守预留计算；任一预算超限立即在网络前拒绝本次请求。
月预算3元可能先于31天各0.1元的日预算总和耗尽，较严格者生效。
到新日/月只计算新窗口，不清空旧调用、原费用或全生命周期次数。

PostgreSQL对GuardState唯一行SELECT FOR UPDATE，包住计数/求和/预留插入；
SQLite离线替代使用BEGIN IMMEDIATE。进程锁和防重仍保留。
这不把应用升级为多worker系统：启动恢复会把遗留RUNNING/SENT_UNCERTAIN视为中断，仍限定单worker运行。
SQLite并发已验证，PG锁SQL仅编译通过，真实PG并发要未来独立验证。

## 3. 严格时间策略（用户已选择）

新增last_observed_at保存已确认时间高水位，clock_epoch保存人工时间确认代次。
升级时不重写原created_at/day，初始下界取已有ModelCall与Operation的最大时间和高水位，
即使原操作因额度不足而没有ModelCall，也不能丢掉它的时间证据。

持续运行：启动UTC + 单调时钟elapsed作为预算时间，正常连续运行自动跨UTC日/月。
墙钟只用于一致性检查；回拨到高水位前或与投影相差超过60秒，持久暂停CLOCK_REVIEW_REQUIRED，
API仍用安全USAGE_STOPPED，不创建新付费预留。
容差内的小墙钟调整也不能提前刷新日/月窗口，因为预留仍按单调时钟投影计费。

重启：同一UTC日且不回拨，可以恢复账本；跨日/月或回拨则暂停，不能凭修改系统日期并重启获取新预算。
暂停时guard摘要显示最后确认窗口，避免把错误日期下的0用量误认为新余额。
同日重启及频率窗口仍依赖可信服务器时间；此策略防止日/月预算刷新绕过，不声称能防有权限改DB/程序的管理员。
机器长时间休眠、NTP大校正也可能被严格策略阻断；不能为消除提示自动关闭保护。

恢复必须人工先核对可信UTC、无RUNNING/SENT_UNCERTAIN及所有UNKNOWN/预留：
只有显式--acknowledge-clock与原--acknowledge-uncertain-charges一起使用才可确认时间。
确认不能早于持久化ModelCall/Operation时间；更新高水位/clock_epoch并清除暂停，不改请求、费用、历史基线或防重记录。
运行中的guard看到新epoch会重新校准单调锚点，不要求为清零而重启。
没有自动确认任务、定时清表或自动退费；普通ack-stop不能解除时钟原因的暂停。

这是依赖可信数据库和人工复核的应用保护，没有引入外部授时服务/中间件。
不保证可以抵御同一管理员同时篡改数据库、程序及时间；不把本机预算等同云侧账单硬限额。

## 4. 故障、超额和用户反馈

- 预算/次数耗尽：USAGE_LIMIT/HTTP429；不发送本次付费HTTP，不增加新的ModelCall。
- 频率或忙：USAGE_RATE_LIMIT/USAGE_BUSY；不自动等待重发，不能把失败按钮操作当成功。
- UNKNOWN/中断：暂停、预留保留，须人工核对，不能自动ack或以新审批ID退回额度。
- 时钟：USAGE_STOPPED/HTTP503，后台reason=CLOCK_REVIEW_REQUIRED；普通用户不可确认时间。
- Token：TOKEN_LIMIT/HTTP422；Qwen拒绝前已完成的查询Embedding仍计费。
- 日/月窗口的自然续期不是一次新授权；是否允许日常付费取决于未来正式启用的预算审批范围。

现有聊天页面识别USAGE_LIMIT/USAGE_STOPPED，并在失败/结果不确定时暂停发送，查看历史不会自动重发。
文档后台可能在若干已收费批次后失败，保留安全error_code；列表对部分错误码只有通用失败文案，
应先用后台status/记录定位原因，不能盲目重新上传。这里不增加自动重试或新的前端业务状态。

## 5. 费用、隐私与数据风险

应用上限只覆盖此环境可记录的已知调用。API Key其他客户端、账号泄露、价格变化、隐藏Token或云计费差异不在其控制内。
超出估算的usage会增加保守费用并暂停，不能撤回已发送请求；因此不承诺云账单绝不超限。
建议在云控制台设置账号告警/可用消费控制（本轮未配置或验证），执行时按实际账户能力确认，不假定免费额度。

API Key仅后端原安全机制读取，不能进入前端、镜像、日志或审计。
使用量日志仅含事件码、call_id、数量和费用，不含原文、问答全文、密码或Authorization。
业务数据库保存消息/片段是系统功能，并非日志脱敏；个人文档/DB卷目前不是自动加密存储。
上传/问答会按需要向云模型发送文本，用户应确认个人资料适合云处理；本轮未使用真实个人数据。
备份含个人资料与认证哈希，需要限制ACL和安全保管，不把模型Key放进普通数据归档。
