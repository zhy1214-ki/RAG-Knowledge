# Stage 8：真实端到端验收与V1.0发布

本Stage是开发历程专题，不是历史Git版本。运行结论来自限定范围的既有记录，本轮不执行验收。

## 1. 阶段目标

取得浏览器、后端、持久化存储和真实模型之间可追溯的链路证据，再以独立脱敏源码发布。对应真实后端验收、M5、R3.3、R4.6和G阶段，不代表所有真实测试发生在最后一个阶段。

## 2. 技术与依赖

复用已验证的FastAPI、Vue、PostgreSQL、Milvus、Qwen和Embedding组件及受控执行器。测试只用合成材料，按执行前审批限制调用数，失败或结果不确定即停止；上传、索引和问答不能自动重试。

## 3. 实现内容

验收分开保存离线/Mock、真实数据库与向量设施、真实后端RAG、真实浏览器RAG、8080合成UI及8081真实链路结果。发布副本采用全新本地Git历史，不导入旧提交、标签、归档、实际审批和用户数据。

## 5. 关键实现流程

核对模式、时间、账本和资源 → 登录 → 既有知识库 → 合成文档上传一次 → 解析/分块/文档Embedding → Milvus索引 → 提问一次/查询Embedding → 检索 → Qwen → 答案和引用 → 历史读取 → 核对调用及预算。断点续验先验证原资源仍在且归属正确，再复用向量，不根据旧PASS直接推断当前可用。

## 6. 测试与验证结果

H02首次真实后端2 Embedding+1 Qwen PASS；H03 M5 V3再2+1真实浏览器PASS；H07 R3.3复用索引1+1 PASS。H09 R4.6合成故障制度中“15分钟响应、4小时恢复”回答、引用和历史匹配，新增2 Embedding+1 Qwen，累计11到14。不是本轮新调用或当前余额。

## 7. 遇到的问题及解决方案

M5目录门禁和存储预检、R3导航及后续时钟门禁曾阻断，原失败均保留。需要部署或恢复时重新独立授权，不改变旧清单来绕过；已收费索引优先断点复用。Public展示只写脱敏范围，不把本地原始审批/认证请求放入仓库。
