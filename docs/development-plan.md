## 实施依赖

基础架构 → 认证/知识库归属 → 文档解析与分块 → 向量索引 → 问答与引用 → 分层验收。
前端与这些API并行演进；真实环境、安全门禁和部署证据在独立授权后完善。当前任务只整理文档，不执行上述开发、部署或模型调用。

- 先用Mock模型验证接口与失败路径，再分别验证真实PostgreSQL和Milvus持久化。
- 模型适配通过替身测试不等于真实Qwen/Embedding通过；真实调用需要独立授权和次数预算。
- UI Mock检查、真实后端RAG、真实浏览器RAG分别记账，不能相互替代。
- 后期对费用、时钟和执行器的定向回归不与早期测试简单相加。

## 文档与证据规则

[系统架构](ARCHITECTURE.md)描述当前实现；[开发历程](development-history.md)记录H01～H10脱敏证据与历史阻断。每份Stage保持相同九节，代码位置链接到本仓库实际文件。

原始运行日志、审批、账号、截图和费用账本不随源码分发；只有经过整理的范围、结论和代码对应关系进入公开文档。相关边界见[本地材料说明](LOCAL_EVIDENCE_INDEX.md)。不通过补造源码、同名附件或伪造提交来补齐历史。

## 已知边界与待验证事项

当前没有OCR、SSO、通用角色系统、高可用任务队列或多worker共享Milvus方案；接口没有通用全站限流。真实运行的费用门禁不等同于云侧账单绝对上限。

大规模检索/回答质量、生产并发性能、跨平台覆盖、远程部署和HTTPS等不能由单文单问或历史本机PASS推出。新增这些能力需要另立任务，不属于本次开发完成范围。

本次新增文档尚未提交或推送。维护者说明仓库已为Public；本轮不访问远端核验可见性，也不修改GitHub设置。所有公开文档都按不含秘密和个人信息的标准整理。
